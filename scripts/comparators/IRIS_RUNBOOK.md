# LUAD/AIS comparator benchmark — runbook for iris

**Audience.** Part 1 is for whoever (or whatever) sets the host up — it is written so an
agent can execute it. Part 2 is the run itself, and **the human runs those commands by
hand**; do not run them for them. Parts 3–5 are what to do when something breaks and what
is deliberately absent.

**What this is.** Five cell–cell-communication methods run on four Xenium sections
(`P{17,21}_{AIS,LUAD}`), each following its own authors' default workflow, at one LR-database
tier. The goal for this phase is coverage and persistence: run them, keep every output, hand
the results over for exploration. It is not to produce a statistic.

---

## 0. The decisions this run is built on

Each of these is settled. If you find yourself about to change one, stop and ask.

| decision | value | why |
|---|---|---|
| unit of analysis | **one whole section**, 4 fits | each h5ad is one contiguous tissue with one coordinate frame. Tiling it severs real neighbours (at a 2 mm tile, 13–14 % of true <365 µm neighbour pairs and 57 % of cells' neighbourhoods). GBM's per-core split was legitimate only because its 13 TMA punches are physically separate tissue |
| pooling all four | **never** | the four coordinate frames overlap numerically. CellChat is the one exception and only because it computes distances strictly within `meta$samples` |
| LR tier | **`cellchatdb2` only** | user decision. `default` is skipped; log it as a deviation in each method's `DEVIATIONS.md` |
| requested LR pairs | **none** | GBM's GRN→SORT1 / ANXA1→FPR1 do not transfer, and **ANXA1 is not on the LUAD 5,101-gene panel at all** (verified against all four `var` indices; GRN, SORT1, FPR1 are present). `--requested-lrs ""` everywhere |
| unannotated cells | **dropped in prep** | 380,538 cells, 17–23 % per section. Five of seven runners `.astype(str)` the cell-type column, which turns NaN into a literal `'nan'` cell type that enters every chord plot and every p-value. Dropping also reproduces ALARMIST's own row order |
| methods | **stLearn, SpatialDM, CytoSignal, CellChat, LIANA (inflow + MOFA-Flex)** | COMMOT and NICHES dropped: dense O(N²) edgelists need 0.5–9 TB on these sections, and neither released version exposes a sparse path |
| tracked scripts | **not edited** | LUAD variants are generated by `sed` (regenerable, auditable), and two hardcoded manifest labels are corrected after the run |

## 1. Host setup — this part can be executed by an agent

### 1.1 What to copy to iris

```
scripts/comparators/          the whole tree (code only, small)
data/LRdatabase/CellChatDBv2.0.human.csv
<the four source h5ads>       P{17,21}_{AIS,LUAD}_Xenium.h5ad  (~4.1 GB total)
<the CellChat source clone>   needed: CellChat installs as RemoteType: local, and no lock
                              file contains it. Version must be 2.2.0.9001
```

Do **not** copy `results/comparators/` — it is ~44 GB of GBM output and nothing here reads it.

### 1.2 Resource request

| stage | RAM | notes |
|---|---|---|
| prep | 8 GB | ~1 h |
| stLearn | 8 GB | bin-count driven, not cell-count driven |
| LIANA inflow | 16 GB | |
| LIANA MOFA-Flex (joint) | 96 GB | one fit over all 1.68 M cells |
| CellChat | 96 GB at `--workers 4`, 32 GB at `--workers 1` | LUAD object is 1,200,922 cells |
| CytoSignal | 96 GB | `permuteLR` floors `perm.size` at the cell count |
| **SpatialDM** | **128 GB** | the hungriest: P17_LUAD peaks ~87 GB |

**Ask for one 128 GB node and everything fits.** Disk: **250–300 GB** for outputs, plus
~15 GB for the prepped h5ads.

### 1.3 Build the environments

```bash
CELLCHAT_SRC=/path/to/CellChat bash scripts/comparators/_common/install_envs_iris.sh
bash scripts/comparators/_common/install_envs_iris.sh --check
```

Six envs are built; `bptf` (the prep env: anndata, scanpy, h5py, scipy, pandas, numpy ≤ 1.24)
must already exist or be created separately. Three things the lock files do **not** carry, and
the installer handles each explicitly — read its header if any of them fails:

1. **CellChat** is `RemoteType: local`; you must supply `CELLCHAT_SRC`.
2. **CytoSignal** has no lock file at all. The installer pins GitHub SHA
   `b2c1a3cfda258fa57f6c8c3a92635dfe4b0505a0`. The older bundle installer called
   `install_github()` *without* a ref and would silently give you upstream HEAD.
3. **`comp-nebula`** is a new, minimal R that exists only because `nebula` does not build
   inside `comp-cytosignal`. `run_nebula_stage.R` re-invokes itself there.

Also confirm **presto** is present in `comp-cellchat`: without it `computeCommunProb`'s DEA
falls back to `stats::wilcox.test` **silently**, and CellChat's `thresh.fc` was tuned for
presto. The installer checks and installs it.

### 1.4 Point the config at iris

Edit **one file**, `scripts/comparators/_common/luad_config.sh` — the four `HOST PATHS` at
the top (`REPO`, `LUAD_SRC_DIR`, `LUAD_PREPPED_DIR`, `LUAD_RESULTS_DIR`, `CONDA_ENVS`).
Nothing else in the tree contains a machine-specific path.

Then self-check:

```bash
bash scripts/comparators/_common/luad_config.sh
```

It prints OK/MISS for every directory, the four source h5ads, and all seven interpreters.
`LUAD_PREPPED_DIR` reporting MISS before prep has run is expected. **Everything else must
say OK before you continue.**

### 1.5 Dry-run everything

Every run script takes `--dry-run`, which prints the exact command lines and executes
nothing:

```bash
for s in 00_prep 01_stlearn 02_spatialdm 03_cytosignal 04_cellchat 05_liana; do
  bash scripts/comparators/run_luad/$s.sh --dry-run
done
```

`01`–`05` will refuse until prep has run (they need `prep_manifest.json`); that is the
guard working. Run `00_prep.sh --dry-run` first, then hand over to the human.

## 2. The run — the human executes these, one at a time

Each script is independent once prep is done, and each prints what it is about to do before
doing it. Run them in this order; the order is by cost and by risk, so the cheap things
validate the prep artifact before anything expensive commits.

### Step 0 — prep (~1 h, 8 GB, ~15 GB out)

```bash
bash scripts/comparators/run_luad/00_prep.sh
```

Builds the four prepped h5ads + one concatenated file, generates the two CellChat LUAD
variants, and builds the LUAD-specific LR resources. **Read the tail of its output**: it
prints the stLearn grid geometry per section and any cell-type substring collisions.

Sanity numbers to expect (annotated cells): 182,378 / 640,739 / 292,862 / 560,183 =
**1,676,162**. If that total is different, stop — it should match
`results/AIS_LUAD/single_cell/cell_loadings.npy`'s 1,676,162 rows, which is what makes
`obs['alarmist_row']` a valid join key.

### Step 1 — stLearn (~1.5–4 h per section, 8 GB, ~15 GB out)

```bash
bash scripts/comparators/run_luad/01_stlearn.sh
# or one at a time:
bash scripts/comparators/run_luad/01_stlearn.sh P17_AIS
```

Four independent runs. **No native multi-sample mode** — stLearn emits no between-condition
statistic, so the AIS-vs-LUAD reading is four `lr_summary` tables side by side. That is a
capability gap and gets reported as one.

### Step 2 — SpatialDM (~3 h, **128 GB**, largest disk item)

```bash
bash scripts/comparators/run_luad/02_spatialdm.sh
```

Four per-section fits, then **its own native differential** (`concat_obj` →
`differential_test` → `group_differential_pairs`), which is one of the two tutorials on the
package's front page.

### Step 3 — CytoSignal (~4–8 h, 96 GB)

```bash
bash scripts/comparators/run_luad/03_cytosignal.sh
```

Four per-section significance runs, then **`mergeCytoSignal` + `runNEBULA`** on `stage` —
a fitted model coefficient, not us comparing two tables. `--skip-significance` runs only the
differential; `--pairs` merges within patient instead of pooled.

### Step 4 — CellChat (~4–12 h, 96 GB at `--workers 4`)

```bash
bash scripts/comparators/run_luad/04_cellchat.sh
# lower memory, ~4x slower:
bash scripts/comparators/run_luad/04_cellchat.sh --workers 1
```

Two objects (one per condition, two sections each as `meta$samples`), then `mergeCellChat`
and the whole comparison stack. **The only method that legitimately holds several sections
in one object.** Watch `plots/` — the GBM run emitted 9,256 files.

### Step 5 — LIANA (~2–4 h, 96 GB for the joint fit)

```bash
bash scripts/comparators/run_luad/05_liana.sh
# skip the joint fit:
bash scripts/comparators/run_luad/05_liana.sh --skip-mofaflex
```

Four per-section `inflow` runs, then **one joint MOFA-Flex fit** over all four — the only
LIANA branch that puts the sections in a shared factor space.

## 3. Traps, in the order you are likely to hit them

1. **`--count-layer X` is fatal for SpatialDM and wrong for CytoSignal.** After prep, `X` is
   log1p(CP10K) and the raw counts are in `layers['counts']`. Every run script already passes
   `--count-layer counts`; do not "simplify" it. SpatialDM builds `.raw` from that layer and
   `spatialdm/utils.py:181` dereferences `.raw` — with `X` it is `None` and the run dies
   *after* the expensive global pass. `cytosignal/export_cs_input.py` reads `layers['counts']`
   and asserts integrality precisely so a log matrix can never be cast to `int32`.

2. **Never give stLearn or LIANA the concatenated file.** `st.tl.cci.grid()` bins the global
   bounding box; `li.ut.spatial_neighbors` builds one graph over the whole object and
   `--punch-col` is metadata only. Four overlapping frames become one tissue. The run scripts
   use the per-section files; only `04_cellchat.sh` reads the concatenated one.

3. **`spatial_factors.csv` row order is positional.** `computeRegionDistance` indexes
   `ratio[k]` / `tol[k]` over `levels(meta$samples)` (`CellChat/R/modeling.R:1165,1212`). A
   wrong order silently applies the wrong µm conversion. `prepare_gbm_input.py` writes it
   correctly; never hand-edit it.

4. **CytoSignal plots only for P17_AIS.** `run_cytosignal.R:69` gates figures at ≤ 200,000
   cells and only P17_AIS (182,378) is under it. Three sections ship quantitative output and
   no images. That is the tracked script's own behaviour, left alone deliberately.

5. **The CytoSignal merge may hit an int32 wall.** 1,676,162 cells × ~2,683 interactions =
   ~4.5 × 10⁹ elements against `dgCMatrix`'s 2,147,483,647 `@i` cap. If it dies with a length
   or allocation error, re-run with `--pairs`, which merges within patient. Given the matched
   2×2 design that is arguably the better analysis anyway.

6. **`selectK` must run in a fresh process.** It calls `NMF::nmfEstimateRank` with NMF's
   parallel foreach backend and dies with *"All the runs produced an error"* in a session that
   has already done Seurat/ComplexHeatmap work — the identical call succeeds in a clean
   session. `04_cellchat.sh` already invokes the plotting script separately.

7. **`netAnalysis_river` needs `ggalluvial` attached, not merely installed.** ggplot2 resolves
   `stat = "stratum"` off the search path. This cost the GBM run all 8 river plots on the
   first pass.

8. **Empty `plots/requested*/` directories are expected output**, not lost output — no LRs of
   interest were named for this dataset. Say so in the write-up so nobody reads them as a
   failure.

## 4. What is deliberately NOT run

State each of these explicitly in `METHODS.md`; none is a failure.

| absent | why |
|---|---|
| **COMMOT** | `_spatial_communication.py:390` builds `distance_matrix(spatial, spatial)` unconditionally — 496 GB (P17_AIS) to 6.1 TB (P17_LUAD) counting the kernel copy. `cot_sparse` only operates on already-thresholded submatrices; the dense N×N is built first. No escape in the released version |
| **NICHES** | `ComputeEdgelist.R:35-56` builds three dense N×N doubles — 743 GB to 9.2 TB. The `nn.method` fast path is **entirely commented out** (lines 76–146) and `RunCellToCellSpatial` never passes the argument |
| LIANA bivariate, bivariate-morans, NMF (both inputs), LR-MISTy, LRIC/cross-PCF | out of scope for this run by user decision |
| `run_inflow_downstream.py` | structurally incompatible. `:114-118` requires a real `--region-col`, and everything it adds is conditioned on that column being a *within-object* contrast (`:237-238` `compute_global_specificity(groupby=REG)`, `:245-246` `f"{CT}::{REG}"`). Inflow is per section and a section is exactly one stage, so the contrast is empty by construction. Feeding it a constant column would produce a one-level "comparison" that looks like a result |
| `annotate_factors.py` | reads `nmf_<branch>/data/NMF_H_loadings.csv` (`:368-369`). NMF is out of scope, so it has no input. A MOFA-Flex-aware variant would be new work |
| `spatialdm/compare_tiers.py` | needs both a `default` and a `cellchatdb2` tree; only `cellchatdb2` is being run |
| the `default` tier | user decision. On GBM, where both tiers were run, the LR resource changed which pairs are tested and the ranking denominator but **not any per-pair statistic** (SpatialDM Pearson r = 1.000 on shared pairs; LIANA max \|Δ\| = 0.0 on 23,787 rows; CellChat bit-identical). For CellChat "default" is not even a different database — the bundled `CellChatDB.human` already *is* v2 and the tier only selects annotation categories (`subsetDB(search="Secreted Signaling")` = 1,280 interactions vs `subsetDB(CellChatDB)` = 2,239) |

## 5. Reading the results afterwards — two things that will silently mislead

1. **Join cells by `obs['alarmist_row']`. Do not join by LRI name.**
   `results/AIS_LUAD/` was fitted with the **pre-2026-07-28** CellChatDB export; these
   comparator runs use the current one, and **1,120 of 3,218 LR keys changed** between them
   (complex subunits were reordered, e.g. `RAMP2_CALCR` → `CALCR_RAMP2`; some ligands became
   homo-complexes, `ALDH1A1` → `ALDH1A1_ALDH1A1`). Only 2,097 keys are shared. `alarmist_row`
   indexes straight into `results/AIS_LUAD/single_cell/cell_loadings.npy` (1676162 × 25).

2. **Every cross-stage test here is n = 2 vs 2, and one of them is anti-conservative.**
   SpatialDM's `differential_test` fits a 2-parameter OLS (2 residual df) but scores it with
   `chi2.sf(LR_statistic, 1)` — df hardcoded to 1. A clean separation like
   z = [0.5, 6.0, 0.6, 5.8] returns p = 1.1 × 10⁻⁷. LIANA's section-level rank test floors at
   p = 0.333 and can never reach 0.05. CytoSignal's NEBULA random effect has four levels while
   the model sees ~1.5 M cell-level observations. CellChat's and NICHES-style tests are at
   cell / cell-group granularity, which is pseudoreplication with respect to the section.
   And patient is perfectly confounded with the pairing: P17 and P21 each contribute one AIS
   and one LUAD section, and **no method's native test uses that pairing.**
   Treat all of it as exploratory ranking.
